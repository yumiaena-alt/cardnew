# 01. PRD — Panelo

기준일: 2026-08-02 · 버전 0.3

## 1. 한 줄 정의

**혼자 여러 SNS 채널을 운영하는 1인 사업자가, 한 달에 한 번 앉아서 한 달치 콘텐츠를 만들고 예약까지 끝내는 도구.**

## 2. 문제 정의

### 2-1. 타깃

| 항목 | 내용 |
|---|---|
| 1차 | 1인 사업자·소상공인 (카페, 공방, 학원, 프리랜서 코치, 스몰 브랜드 대표) |
| 채널 운영 | 인스타그램 필수 + 스레드/릴스/블로그 중 1~2개 병행 |
| 발행 빈도 | 주 2~4회 |
| 디자인 역량 | 낮음~중간. Canva를 쓰지만 매번 처음부터 만듦 |
| 예산 감각 | 월 2~3만 원까지는 지불. 그 이상은 "직원 쓰는 게 낫다"로 넘어감 |

### 2-2. 실제 고통 (우선순위 순)

1. **같은 얘기를 채널마다 다시 만든다.** 인스타 카드뉴스를 만들고, 릴스 커버를 또 만들고, 블로그에 다시 쓴다. 같은 소재인데 작업은 3번.
2. **매일 "오늘 뭐 올리지"를 결정해야 한다.** 결정 피로가 발행 중단의 1순위 원인.
3. **디자인 일관성이 무너진다.** 만들 때마다 폰트·색이 조금씩 달라져 계정 그리드가 지저분해진다.
4. **AI 도구를 써도 결과가 한 번에 안 나온다.** 마음에 안 들면 전체를 다시 뽑아야 하고, 그때마다 비용이 든다.

### 2-3. 경쟁 제품(Mirr) 대비 우리의 진입점

Mirr는 기획→제작→발행→분석 전 구간을 넓게 덮지만, 실무 관점에서 세 가지가 비었다.

| 갭 | 근거 | Panelo의 대응 |
|---|---|---|
| **연동 게이트가 가치 체험을 봉쇄** | 캘린더 예약·성과·댓글·DM 전부 SNS 연동 전에는 빈 화면. 무료체험 D-3인데 만질 게 없음 | 읽기 전용 데모 Board를 가입 즉시 제공. 연동은 발행 시점에만 요구 |
| **생성이 올아어낫싱** | 15크레딧 태워야 결과 확인, 기획 검토 토글 기본 OFF, 부분 수정 경로 없음 | Slot 1cr / Panel 3cr 단위 재생성 + 실행 전 dry-run 견적 + 실패 자동 환불 |
| **아이디어→초안→예약→성과가 단절** | 생성기록·캘린더·성과가 각각 독립 화면 | Board 1행이 소재부터 성과까지를 관통하는 단일 레코드 |

> 관찰 시 발견한 결함: 설정 화면에 `Navbar.currentWorkspace:` i18n 키 원문 노출. 우리는 `check:i18n`을 CI 차단 게이트로 둔다.

## 3. 솔루션 — Board

### 3-1. 핵심 개념

```
❌ 에이전시형 벌크 (가로 확장)        ✅ Panelo의 벌크 (세로 + 시간)
   브랜드A ─ 30건                        소재 1개 ─┬─ 인스타 카드뉴스 4:5
   브랜드B ─ 30건                                  ├─ 릴스 커버 9:16
   브랜드C ─ 30건                                  ├─ 스레드 텍스트
                                                   └─ 블로그 초안
                                        + 월 1회 앉아서 한 달치 세팅
```

1인 사업자에게 "벌크"란 건수를 늘리는 것이 아니라 **한 소재를 여러 채널로 펼치는 것**과 **한 달치를 한 번에 끝내는 것**이다.

### 3-2. 3대 기능

#### F1. Fan-out — 1행 → N채널 (P0)

| 소재 | 인스타 4:5 | 릴스 9:16 | 스레드 | 블로그 |
|---|---|---|---|---|
| 여름 신메뉴 3종 | ✅ 8장 | ✅ 커버 | ✅ | ⬜ |

- 원본 Deck 1회 생성 후, 파생 Cut은 본문 재활용 + 리레이아웃만 수행
- 채널별 톤 조정은 브랜드킷 규칙 기반 (인스타=친근체, 블로그=정보체)
- 과금: 원본 15cr, Cut 5cr → 3채널 총 25cr

#### F2. 월간 배치 세션 (P0)

```
"8월 캘린더에 12칸이 비어 있어요"
  → 시리즈 템플릿 적용 (매주 화 = 팁 / 금 = 후기)
  → 주제 12개 입력 (또는 AI 제안 수락)
  → Dry-run: 12행 × 평균 22cr = 264cr / 잔여 500cr
  → 일괄 생성 → 캘린더 자동 배치
```

목표: **월 1회 30분 이내에 한 달치 세팅 완료.**

#### F3. 시트 조작감 (P0)

Google Sheet 붙여넣기, 드래그 필 핸들, 다중 셀 편집, `⌘Z` 실행취소, 실패 행만 재시도.

### 3-3. 지원 기능

| 기능 | 우선순위 | 설명 |
|---|---|---|
| Slot/Panel 단위 재생성 | P0 | 1cr / 3cr. Board 편집 중 즉시 수정 |
| Dry-run 견적 | P0 | 모든 생성 API의 1급 파라미터 |
| 디자인 학습 | P1 | 레퍼런스 이미지 ≤10장 → 내 템플릿 (5cr) |
| 브랜드킷 | P1 | 로고·팔레트·폰트·금칙어·말투 고정 |
| 예약 발행 | P1 | Instagram → Threads → TikTok → YouTube 순 |
| 성과 대시보드 | P1 | 발행 후 7/14/30일 지표 수집 |
| 소재 중복 감지 | P2 | 임베딩 유사도 ≥0.85 경고 |
| `⌘K` 커맨드 팔레트 | P2 | 전역 검색 + 액션 |

### 3-4. 정보 구조 (IA)

프로젝트에 배치된 v0 셸의 메뉴는 Mirr 구조를 복제하고 있다. Board 중심으로 재구성한다.

| v0 (Mirr 복제) | → | Panelo | Phase |
|---|---|---|---|
| AI로 기획 › 콘텐츠 기획 | → | **Board** — 이번 달 배치 | 2 |
| AI로 기획 › 레퍼런스 리서치 | → | 폐기 | — |
| AI로 콘텐츠 제작 › 콘텐츠 만들기 | → | **Deck** — 새로 만들기 / 내 Deck | 1 |
| — | → | **템플릿** — 갤러리 / 디자인 학습 | 1·2 |
| 콘텐츠 캘린더 | → | 캘린더 | 3 |
| 콘텐츠 성과 | → | 성과 | 3 |
| 자동 DM · 댓글 관리 | → | 폐기 | 4 재검토 |

Phase 1에서는 **Deck / 템플릿 / 설정** 3개만 노출한다. 빈 메뉴를 미리 깔아 두지 않는다 — Mirr의 가장 큰 UX 실패가 "눌러도 아무것도 없는 메뉴"였다.

### 월 사용 시뮬레이션 (주 3회 발행 · 3채널 팬아웃)

```
소재 12개 × (원본 15 + Cut 5×2)  = 300cr
수정 여유 (Slot 재생성 50회)      =  50cr
                        합계 ≈ 350cr  →  Standard 500cr 내 안착 (여유율 30%)
```

## 7. 법적 필수 요소

| 항목 | 요구사항 |
|---|---|
| 이용약관 | 크레딧은 **선불 이용권** — 유효기간·소멸 조건 명시. AI 산출물 정확성 면책 |
| 개인정보처리방침 | 처리위탁 목록(Clerk·Supabase·Vercel·Stripe·LLM 제공사), **국외이전 고지**(국가·항목·시점·거부권) |
| 동의 분리 | 필수(약관·개인정보) / 선택(마케팅 수신) 완전 분리. 채널별 개별 동의. 동의 시각 DB 기록 |
| 회원탈퇴 | 앱 내 자기서비스 → 즉시 접근 차단 → **30일 유예 후 하드 삭제**. "즉시 파기" 옵션 병행 |
| **AI·저작권** | ① 레퍼런스 업로드 시 "권리 보유 확인" 체크 강제 ② 산출물 저작권 사용자 귀속·유사성 책임 사용자 부담 ③ 학습 이미지는 **해당 워크스페이스 전용**, 타 조직 학습 미사용 명시 |
| 플랫폼 정책 | Meta/TikTok/YouTube 개발자 약관 준수. 발행 빈도 제한 준수 |
| 전자상거래 | 사업자 정보·통신판매업 신고번호 푸터 표기. 자동갱신 사전 고지. 환불 규정(중도해지·크레딧 잔액) |
| 기타 | 만 14세 미만 가입 제한. WCAG 2.2 AA. 쿠키 배너(분석 도구 기본 OFF) |
